# 从数据本身理解生物学

本仓库的学习单位不是软件名称，而是“测量—数据—模型—证据”之间的对应关系。

## 一条固定的阅读顺序

科学问题 → 实验单位与对照 → 测量技术 → 原始数据 → 质量控制 → 特征提取 → 统计或预测模型 → 生物学解释 → 独立验证。

读方法时，先写清六个问题，再查工具如何运行。

| 问题 | 需要记录的内容 |
| --- | --- |
| 实际测了什么？ | 仪器原始信号；信号对应的生物学过程；直接测量还是代理读出 |
| 输入是什么？ | 文件格式、矩阵维度、单位、参考版本、样本元数据 |
| 谁是独立样本？ | 个体、培养批次、细胞、视野及技术重复的层级关系 |
| 模型假设是什么？ | 分布、独立性、稳态、归一化、缺失机制、训练分布等 |
| 输出代表什么？ | 效应量、概率、相似度、相对次序、预测值及其不确定性 |
| 什么能推翻解释？ | 替代解释、负对照、敏感性分析、独立数据或干预验证 |

## 为每项结果标明证据性质

在自己的笔记里，将结果标为“测量/重建”“描述/关联”“模型预测”或“干预效应”，不要把它们直接互换。进一步写明该结果能够支持什么，以及仍缺少什么证据。

可以从这些例子练习：用 [M059](../atlas/domains/07-single-cell.md#m059) 区分细胞状态与组成；用 [M063–M067](../atlas/domains/08-dynamics-lineage.md#m063) 区分拟时序、方向和谱系；用 [M073](../atlas/domains/09-spatial-omics.md#m073) 理解候选通信；用 [M117](../atlas/domains/15-structural-biology.md#m117) 区分结构预测与实验重建。

## 每读一个方法，做一份最小记录

从 [方法模板](../templates/method.md) 开始。至少保留一个真实输入片段、一张中间结果图、一份最终结果表，以及一句明确的证据边界。没有亲自运行时，标记为“读过”，而不是“已复现”。

涉及实验的部分使用 [实验模板](../templates/experiment.md)；论文按 [论文模板](../templates/paper.md) 拆解；完整流程放入 [案例模板](../templates/case-study.md)。

## 内容的使用边界

初始内容是按方法家族归并的学习索引，不是系统综述，也不表示每个软件都经过本仓库实测。方法名称、工具维护情况和文档会变化；用于具体项目时，回到 [原始资料](../references/index.md) 核对假设、版本与适用数据。
